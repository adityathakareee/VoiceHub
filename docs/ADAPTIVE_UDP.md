# CSE VOICE HUB — ADAPTIVE UDP RATE CONTROL & RESILIENCE

## 1. Overview
The **Adaptive UDP Engine** provides dynamic rate adaptation, packetization elasticity, application-level redundancy (FEC), and jitter buffer regulation over unreliable UDP transport. It employs a deterministic **Additive Increase / Multiplicative Decrease (AIMD)** algorithm coupled with hysteresis deadbands to maximize audio fidelity during pristine network conditions while mitigating congestion, packet loss, and buffer underruns during network degradation.

> [!NOTE]
> This system is a deterministic, rule-based **Adaptive Networking Control Algorithm** grounded in RFC 3550 and RFC 2198 principles. It does not utilize machine learning or neural networks.

---

## 2. Transmission Profiles Matrix

The adaptive controller operates across five transmission profiles:

| Profile | Target Bitrate | Frame Duration | Audio Samples (16kHz) | Raw PCM16 Wire Bytes | Primary Codec Mode |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`ULTRA`** | 96 kbps | 15 ms | 240 samples | 480 bytes | PCM16 Linear |
| **`HIGH`** | 80 kbps | 20 ms | 320 samples | 640 bytes | PCM16 Linear |
| **`STANDARD`** | 64 kbps | 20 ms | 320 samples | 640 bytes | PCM16 Linear |
| **`CONSTRAINED`** | 32 kbps | 25 ms | 400 samples | 800 bytes raw $\to$ 400 B | PCM8 Companded |
| **`CRITICAL`** | 16 kbps | 40 ms | 640 samples | 1280 bytes raw $\to$ 320 B | PCM8 Decimated $\times 2$ |

## 3. Telemetry Inputs & Quality Assessment

Every evaluation interval (nominally 1000 ms), the `AdaptiveRateController` ingests real-time network telemetry generated by the Phase 7 collector:
1. **Round-Trip Time (RTT):** Measured via periodic UDP `PING`/`PONG` exchanges.
2. **Inter-Arrival Jitter (RFC 3550):** Calculated recursively on the receiver:
   $$D(i, j) = (R_j - R_i) - (S_j - S_i)$$
   $$J_i = J_{i-1} + \frac{|D(i, j)| - J_{i-1}}{16}$$
3. **Packet Loss Percentage:** Measured using rolling 32-bit sequence number gap accounting.
4. **Network Quality Classification:** Categorized as `EXCELLENT`, `GOOD`, `FAIR`, or `POOR`.

## 4. Formal Adaptive Algorithm Specification

### A. Dynamic Playout Buffer Regulation
To protect against jitter-induced packet late arrival while keeping conversational delay minimal, the target playout delay is dynamically scaled and clamped:
$$\text{targetPlayoutDelayMs} = \text{clamp}\Big(20\text{ ms},\; 200\text{ ms},\; \text{round}(2.5 \times \text{jitterMs} + 0.1 \times \text{rttMs} + 15\text{ ms})\Big)$$

### B. Forward Error Correction (FEC) Hysteresis
FEC redundancy is governed by a split-threshold deadband to eliminate rapid flapping:
- **Activation:** $\text{packetLossPercent} \ge 2.0\% \implies \text{fecActive} = \text{true}$
- **Deactivation:** $\text{packetLossPercent} < 1.0\% \implies \text{fecActive} = \text{false}$
- **Deadband ($[1.0\%, 2.0\%]$):** FEC retains its previous state.

### C. AIMD Profile State Transitions

```
                                  [Nominal Recovery]
                 +-------------------------------------------------+
                 |                                                 |
                 v                                                 |
+-----------------------------------+     Pristine (1 int)     +---v-------------------------------+
|             STANDARD              | -----------------------> |               HIGH                |
|      (64 kbps, 20ms, 320s)        | <----------------------- |       (80 kbps, 20ms, 320s)       |
+-----------------------------------+        Loss > 1.0%       +-----------------+-----------------+
      ^                       |                                                  |
      |                       | Moderate Congestion                              | Pristine (3+ int)
      |                       | (Loss > 3% or RTT > 150ms)                       v
      |                       v                                +-----------------------------------+
      |         +-----------------------------------+          |               ULTRA               |
      |         |            CONSTRAINED            |          |       (96 kbps, 15ms, 240s)       |
      |         |   (32 kbps, 25ms, 400s + FEC)     |          +-----------------------------------+
      |         +-----------------+-----------------+
      |                           |
      | Recovery                  | Severe Congestion
      | (1 int)                   | (Loss > 8% or RTT > 300ms)
      |                           v
      |         +-----------------------------------+
      +-------- |             CRITICAL              |
                |   (16 kbps, 40ms, 640s + FEC)     |
                +-----------------------------------+
```

#### Transition Rules:
1. **Multiplicative Decrease (Severe Congestion):**
   - Condition: $\text{loss} > 8.0\%$ OR $\text{RTT} > 300\text{ ms}$ OR $\text{jitter} > 60\text{ ms}$ OR $\text{rating} = \text{POOR}$.
   - Action: Multiplicatively down-throttle profile to **`CRITICAL`** (16 kbps). Reset consecutive pristine counter.
2. **Congestion Throttling (Moderate Degradation):**
   - Condition: $\text{loss} > 3.0\%$ OR $\text{RTT} > 150\text{ ms}$ OR $\text{jitter} > 30\text{ ms}$ OR $\text{rating} = \text{FAIR}$.
   - Action: Throttle profile to **`CONSTRAINED`** (32 kbps). Reset consecutive pristine counter.
3. **Additive Increase (Pristine Conditions):**
   - Condition: $\text{loss} \le 1.0\%$ AND $\text{RTT} \le 60\text{ ms}$ AND $\text{jitter} \le 15\text{ ms}$ AND $\text{rating} = \text{EXCELLENT}$.
   - Action: Increment consecutive pristine interval counter.
     - If in `CRITICAL` or `CONSTRAINED`: Step up to **`STANDARD`**.
     - If in `STANDARD`: Step up to **`HIGH`**.
     - If consecutive pristine intervals $\ge 3$: Step up to **`ULTRA`**.
4. **Nominal Conditions:**
   - Condition: $\text{loss} \le 3.0\%$ AND $\text{RTT} \le 150\text{ ms}$ AND $\text{jitter} \le 30\text{ ms}$.
   - Action: Maintain or transition to **`STANDARD`**.

## 5. RFC 2198-Inspired Application Redundancy Codec

When FEC is active, audio frames are packaged with redundant samples from the immediately preceding sequence number ($N-1$). To guarantee that packets never violate the 1200-byte wire MTU:
1. **Non-Linear PCM Companding:** 16-bit linear PCM samples ($[-32768, 32767]$) are compressed into 8-bit non-linear integer representations ($[-128, 127]$), halving payload byte size.
2. **Decimation:** For large frames (400–640 samples), redundant samples are downsampled by decimation factors of 4 to 8.
3. **Reconstruction:** On receipt of packet $N$, if packet $N-1$ was lost, the receiver extracts the redundant companded payload, expands it back to 16-bit linear PCM, and interpolates decimated samples to reconstruct the lost frame with 100% temporal continuity.
